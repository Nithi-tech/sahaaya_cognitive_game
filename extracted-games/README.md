# extracted-games

Self-contained snapshot of every game route from **freefocusgames**, generated by
walking the static import graph of `app/[locale]/(main)/games/**` and copying in
everything it actually depends on. Paths are kept **repo-root-relative** (same
layout as the source project) so the `@/*` → project-root TS path alias still
resolves once this folder's contents are merged into a project that defines the
same alias.

This is a **copy for porting into another project**, not a runnable app on its
own — there's no `next.config.ts`, no `app/layout.tsx`, no `node_modules`. See
"How to wire this in" below.

## What's in here

```
app/[locale]/(main)/games/   30 games + the games listing page (page.tsx) + layout.tsx
app/[locale]/globals.css     Tailwind v4 theme + custom utilities the UI kit needs
app/api/leaderboard/         leaderboard API route (see "Leaderboard" caveat below)
components/                  shared UI: GamePageTemplate, GameHeader, shadcn ui/, magicui/, sudoku/, leaderboard-display
data/                        games.tsx (game registry/metadata) + categories.ts
hooks/                       useInterval, useTimeout
i18n/                        next-intl routing.ts, navigation.tsx, request.ts
lib/                         analytics, leaderboard client+config+snapshots, scoring rules, sudoku engine, utils
messages/en, messages/zh     ALL translation namespaces (copied whole — not import-traced,
                              since next-intl loads them by locale, not by static import)
middleware.ts                next-intl locale routing middleware
public/games/, public/embedded/, public/sounds/, public/og/
                              game images, audio, the bamboo-cicada 3D embed, share-card logo
drizzle/*.sql                leaderboard table migrations (Cloudflare D1)
tailwind.config.ts, postcss.config.mjs, components.json
package.json                 exact dependency versions pulled from the source repo
scripts/build-i18n-compiled.js
                              builds messages/{locale}/compiled.json from the per-namespace
                              JSON files (i18n/request.ts loads the compiled file, not the
                              individual namespaces)
```

## How to wire this in

1. **Copy the tree over.** Merge every top-level folder here into the matching
   folder in the target project (e.g. this `app/` merges into the target's
   `app/`, this `components/` into the target's `components/`, etc.).
2. **TS path alias** — target project's `tsconfig.json` needs:
   ```json
   "paths": { "@/*": ["./*"] }
   ```
3. **Tailwind v4** — merge `tailwind.config.ts` and the CSS variables/utilities
   at the top of `app/[locale]/globals.css` into the target's global stylesheet
   (the shadcn `ui/` components and the custom `text-gradient` / `btn-success` /
   `btn-destructive` utilities depend on the `hsl(var(--...))` design tokens
   defined there).
4. **next-intl** — the games use `useTranslations()` / `getTranslations()`
   throughout, so the target project needs next-intl configured the same way:
   `middleware.ts`, `i18n/routing.ts`, `i18n/navigation.tsx`, `i18n/request.ts`,
   and `next.config.ts` wrapped with `createNextIntlPlugin()`. Run
   `node scripts/build-i18n-compiled.js` (adjust paths to match the target repo)
   to regenerate `messages/{locale}/compiled.json` after merging message files —
   `i18n/request.ts` imports the compiled file, not the raw namespace JSON.
   If the target project isn't localized, this is the biggest structural
   dependency to unwind — every game component calls `useTranslations`.
5. **Install dependencies** from `package.json` in this folder (versions match
   what the source repo pins). Note: `framer-motion` is imported directly by
   several games but isn't a *direct* dependency in the source repo either — it
   only resolves there because `motion@^12` hoists it transitively. Pin it
   explicitly (done in this `package.json`) rather than relying on hoisting.
6. **Leaderboard API (`app/api/leaderboard/route.ts`) — Cloudflare-specific.**
   Several games (dual-n-back, sbti-test, double-decision, etc.) call
   `/api/leaderboard` and render `components/leaderboard-display.tsx`. That
   route reads a Cloudflare D1 binding named `DB` via
   `@opennextjs/cloudflare`'s `getCloudflareContext()` — it will throw
   ("Cloudflare D1 binding 'DB' is not available") on any non-Cloudflare
   Workers runtime. Options:
   - Deploy the target project on Cloudflare too, add a `d1_databases` binding
     named `DB` in its `wrangler.jsonc`, and apply `drizzle/*.sql` as
     migrations.
   - Or rewrite `route.ts` against whatever DB the target project uses — the
     scoring/validation logic in `lib/leaderboard-snapshots.ts`,
     `lib/leaderboard-config.ts`, `lib/double-decision-score.ts`, and
     `lib/dual-n-back-clear-rules.ts` is plain TS and portable as-is; only the
     `D1DatabaseBinding` read/write calls in `route.ts` are Cloudflare-specific.
   - Or drop the leaderboard feature for the games you don't need it on.
7. **`data/games.tsx` / `data/categories.ts`** drive the `/games` listing page
   and each game's metadata (title, icon, description, thumbnail). Trim these
   if you only want a subset of the 30 games — the per-game route folders
   don't need entries here to render, only the listing page does.
8. **`lib/site-constants.ts`** hardcodes `https://www.freefocusgames.com` as a
   fallback for `SITE_BASE_URL` (used in canonical URLs / share links) — set
   `NEXT_PUBLIC_SITE_URL` in the target project's env, or edit the fallback.

## Regenerating this snapshot

This folder was generated by a script that walks every `import`/`require` in
`app/[locale]/(main)/games/**`, resolves `@/...` and relative specifiers, and
copies the transitive closure — plus a few manually-added entries for things
that aren't reachable via static imports (the leaderboard API route, next-intl
config files, `messages/`, `public/games` and friends). If games are added or
edited upstream, re-run that process rather than hand-editing this copy.
